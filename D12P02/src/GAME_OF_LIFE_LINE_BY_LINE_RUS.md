# `game_of_life.c` — построчное объяснение

Ниже разбор текущего файла `D12P02/src/game_of_life.c` по строкам (смысл каждой строки или небольшой группы строк).

## 1) Подключения и константы

- **1** — подключение `ncurses` для рисования в терминале и чтения клавиш.
- **2** — подключение `stdio` для работы с `FILE`, `fopen`, `fscanf`.
- **4** — высота поля `ROWS = 25`.
- **5** — ширина поля `COLS = 80`.
- **6** — минимальная задержка кадра (ускорение ограничено).
- **7** — максимальная задержка кадра (замедление ограничено).
- **8** — шаг изменения скорости при нажатии A/Z.

## 2) Инициализация поля

### `fill_default` (10–16)
- **10** — объявление функции очистки поля.
- **11–15** — двойной цикл по всем клеткам.
- **13** — каждая клетка ставится в `0` (мертвая).

## 3) Режим запуска (mode)

### `read_mode_from_user` (18–37)
- **18** — функция запрашивает номер режима у пользователя.
- **19** — `mode = 0`, `valid = 0` для цикла запроса.
- **20–33** — пока ввод неверный, выводится приглашение и читается число.
- **23–28** — если число в диапазоне `1..5`, считаем ввод корректным.
- **28–32** — при ошибке ввода выводится сообщение о корректном диапазоне.
- **33–35** — очистка остатка строки после ввода.
- **36** — единственный `return`.

### `preset_path` (40–54)
- **40** — функция возвращает основной путь к файлу пресета.
- **41** — по умолчанию путь `NULL`.
- **42–51** — соответствие mode→файл:
  - 1 → `1.txt`
  - 2 → `2.txt`
  - 3 → `3.txt`
  - 4 → `4.txt`
  - 5 → `5.txt`
- **53** — вернуть найденный путь.

### `preset_fallback_path` (56–70)
- **56** — запасной путь, если запуск не из `D12P02/src`.
- **58–67** — те же пресеты, но с префиксом `./D12P02/src/presets/...`.
- **69** — вернуть fallback-путь.

## 4) Чтение поля из потока/файла

### `read_field_stream` (72–82)
- **73** — перед чтением поле обнуляется.
- **74–81** — чтение матрицы 25x80 из потока.
- **76** — временная переменная для числа.
- **77** — если число успешно прочитано, используем его.
- **78** — любое ненулевое значение нормализуется в `1`.

### `set_demo_glider` (84–93)
- **84** — аварийный шаблон, если пресет не открылся.
- **85–86** — центр поля.
- **87** — очистка.
- **88–92** — ставим 5 клеток «глайдера».

### `load_preset` (95–111)
- **96** — основной путь.
- **97** — fallback-путь.
- **98** — указатель файла.
- **99–101** — пробуем открыть основной путь.
- **102–104** — если не получилось, пробуем fallback.
- **105–107** — если файл открыт, читаем матрицу и закрываем файл.
- **108–109** — если оба пути не сработали, ставим demo-глайдер.

## 5) Тороидальные границы

### `wrap_row` (113–122)
- **114** — копия индекса строки.
- **115–117** — если вышли выше поля, перенос в конец.
- **118–120** — если вышли ниже поля, перенос в начало.
- **121** — вернуть корректный индекс.

### `wrap_col` (124–133)
- То же самое для столбца.

## 6) Логика жизни

### `neighbors_count` (135–147)
- **136** — счётчик соседей.
- **137–138** — обход смещений `-1..1` по строке/столбцу.
- **139** — пропускаем саму клетку `(0,0)`.
- **140–141** — считаем индекс соседа с учетом тора.
- **142** — добавляем значение соседа (`0`/`1`).
- **146** — вернуть число соседей.

### `next_cell` (149–157)
- **150** — значение клетки в следующем поколении.
- **151–155** — правила Conway:
  - живая выживает при 2 или 3 соседях;
  - мертвая рождается при 3 соседях.
- **144** — вернуть новое состояние.

### `evolve` (159–166)
- **160–165** — пройти по всему полю и вычислить новое поле `next`.
- **162–163** — для каждой клетки: соседи → новое значение.

### `copy_field` (168–174)
- Копирует `next` обратно в текущее поле `field`.

## 7) Интерфейс и управление

### `draw_field` (176–185)
- **177–181** — рисуем все клетки:
  - `#` для живой,
  - `.` для мертвой.
-- **182–183** — строка статуса: управление, mode, gen, delay.
-- **184** — обновить экран `refresh()`.

### `process_key` (187–199)
- **188–191** — `A/a`: ускорить (уменьшить задержку до лимита).
- **192–195** — `Z/z`: замедлить (увеличить задержку до лимита).
- **196–197** — `Space`: остановить игру.

### `run_game` (201–215)
- **202** — буфер следующего поколения.
- **203** — флаг работы цикла.
- **204** — стартовая задержка 200 мс.
- **205** — номер поколения.
- **206** — установить таймаут `getch`.
- **207–214** — игровой цикл:
  1. рисуем текущее поле,
  2. читаем и обрабатываем клавишу,
  3. обновляем таймаут,
  4. считаем следующее поколение,
  5. копируем его в текущее,
  6. увеличиваем `generation`.

## 8) Инициализация и `main`

### `init_screen` (217–227)
- **218** — создаём `SCREEN` через `newterm`.
- **219–224** — если успешно, настраиваем режим терминала и клавиатуру.
- **226** — возвращаем указатель на экран.

### `close_screen` (229–234)
- **230–233** — корректное завершение `ncurses` через `endwin` и `delscreen`.

### `main` (236–247)
- **237** — массив поля 25x80.
- **238** — чтение корректного номера режима `1..5` из stdin.
- **239** — указатель на `SCREEN`.
- **240** — загрузка пресета по выбранному номеру.
- **241–244** — инициализация экрана и запуск игрового цикла.
- **245** — корректное завершение `ncurses`.
- **246** — код успешного завершения.

## Быстрый запуск

Из папки `D12P02/src`:

```bash
gcc -Wall -Wextra -Werror game_of_life.c -lncurses -o game_of_life
./game_of_life
```

Управление в игре:
- `A` — быстрее
- `Z` — медленнее
- `Space` — выход
